# 产品计划书

## 1. 项目定义

这是一个面向个人开发者的本地双端工具，用于在 Mac 和 Windows 上统一管理 AI 模型套餐、API、Token Plan、Free Plan 和候选套餐额度，帮助用户每天快速判断“今天该用哪个套餐 / 模型”，并降低套餐到期、额度耗尽、配置失效带来的中断风险。

## 2. 项目名称

- 中文名：模型额度看板
- 目录名：`model-quota-board`

## 3. 目标用户

- 主用户：个人开发者 / 重度 AI 编码工具使用者
- 管理者：用户本人
- 维护者：后续的 Code / OpenCode 执行方

## 4. 核心问题

当前多个平台的套餐、Token Plan、API 余额、免费额度、候选方案分散在不同工具和页面中，存在以下问题：

- 不能统一查看平台、套餐、模型、到期时间和重置窗口
- 无法快速判断今天该优先消耗哪个套餐
- 某些平台接口不稳定，自动抓取不可靠
- 用户不希望同时拼多个工具使用
- 不希望保存真实 API Key、Cookie、账号密码

## 5. 成功标准

满足以下条件视为 1.0 成功：

- 在 Mac 和 Windows 上都能本地使用
- 能统一管理平台、套餐、额度桶、模型、风险备注
- 首页能看出今天推荐使用哪个套餐 / 模型
- 首页能看出哪些套餐快到期、哪些额度低、哪些有风险
- 支持本地导入 / 导出，可在 Mac 和 Windows 之间迁移
- 不保存真实 API Key、Cookie、账号密码
- 即使 Provider 自动适配全部关闭，工具仍然可用

## 6. 失败标准

出现以下任一情况，视为偏离目标：

- 变成从零开发的新系统
- 强依赖网页登录抓取额度
- 强依赖保存真实密钥或 Cookie
- 同时要求用户拼装多个独立工具才能正常使用
- 为了自动化牺牲稳定性，导致台账本身都不可用

## 8. 核心展示字段

11. 风险备注

## 9. 产品原则

1. 不从零开发完整系统
2. 优先使用现成项目作为底座
3. 目标是可靠、稳定、现成、少折腾
4. 不让用户同时拼多个工具使用
5. 底座缺 Provider 时，优先参考现有项目支持方式
6. 第一版只做个人本地工具
7. 不保存真实 API Key、Cookie、账号密码
8. 不做网页登录余额抓取
9. 不追求全自动，优先确保稳定管理和展示
10. Mac / Windows 双端可用

## 10. 底座决策

结论：继续使用 `onWatch`，但只作为底层运行底座，不直接照搬其产品形态。

原因：

- 它是四个参考项目里唯一明确支持 `macOS / Windows`、本地 Dashboard、SQLite、本地数据和后台轮询的单一底座
- `CodexBar` 和 `OpenCode Bar` 都强绑定 macOS 菜单栏
- `ccusage` 更适合作为本地消耗统计参考，不适合做本产品主底座

## 12. 核心用户流程

### 日常使用流程

1. 打开总览页
2. 查看今天推荐使用的套餐 / 模型
3. 查看快到期、低额度、高风险提醒
4. 必要时进入套餐页调整状态或更新额度

### 新平台录入流程

1. 新建平台
2. 新建套餐
3. 配置 Base URL、模型、适合工具
4. 设置额度桶和重置窗口
5. 标记 API Key 状态
6. 添加风险备注

### 迁移流程

1. 在旧机器导出脱敏数据包
2. 在新机器导入
3. 检查路径和配置状态
4. 手动确认缺失的本地配置
