## 目标

把额度、重置、预测和任务栏状态条统一为一套真实数据模型、显示规则和设置语义。重点是让用户能看懂“已用多少、还剩多少、什么时候重置、按当前速度能撑多久”，并能独立选择任务栏显示哪些服务商和额度窗口。

本任务不改变现有 Windows 上游边界、不改 macOS 代码、不重新设计已经确认的浮窗卡片视觉语言；只补齐数据语义、设置覆盖范围、任务栏配置和设置页问题。

## 用户需求拆分

### A. 周额度与预测合并

1. 本周额度使用量与“本周使用量预测”合并到同一个周额度区域，不再出现两个重复的周额度块。
2. 同一块内同时表达：实际使用百分比、按当前速度的预计百分比、领先/落后差值，以及重置前预计可支撑时长（仅在数据足够时显示）。
3. 预测数据不足、没有速率、服务商不提供周额度时，显示明确的“暂无预测/数据不足”，不能显示 `0`、`—` 伪装成真实结果。
4. 预测只作为辅助信息，不改变服务商返回的实际额度；API 余额、Token Plan、请求次数等非百分比余额不能硬套周额度预测。

### B. 额度显示模式

设置中增加一个清晰的全局选项：

- `显示已使用`：进度条和主百分比表示已使用量；
- `显示剩余量`：进度条和主百分比表示剩余量。

现有 `show_as_used` 基础字段可以复用，但本任务必须把“统一数据规则”和“组件独立设置”分开：浮窗、仪表盘/弹出面板、任务栏分别拥有自己的已用量/剩余量选择，不要求三者联动。设置页服务商详情只作为数据预览，跟随当前所在组件的显示上下文。标签、颜色阈值、进度条方向必须和各自选择的数值语义一致，不能出现“显示剩余量但颜色仍按已用量报警”的矛盾。

余额类服务商（例如 API CNY/USD balance）保持“余额”语义，不受百分比开关强行转换。

### C. 重置时间显示模式

现有 `reset_time_relative` 基础字段可以复用，但要补齐两种明确模式：

- `剩余时间`：例如“3 小时 57 分后重置”；
- `预计时间`：按 Windows 本地时区显示“7 月 31 日 15:30 重置”。

要求：

- 日期跨天时必须包含日期，不能只显示时间；
- 相对时间至少按分钟更新，不依赖重新请求服务商；
- 没有 `resetsAt` 时只能显示服务商原始描述或“重置时间未知”，不能自行推算；
- 所有窗口（5 小时、日、周、月、额外窗口）使用同一套格式化规则和本地化 key。

### D. 重置卡的到期信息

重置卡/额度卡需要明确显示“本窗口何时到期/重置”：

- 统一放在窗口标题行的右侧，避免和主百分比争夺层级；
- 同一窗口只能出现一次重置信息，禁止标题、进度条下方、预测卡重复显示；
- 有精确时间时按 B/C 的显示模式渲染；
- 只有描述没有时间戳时保留原描述并标记为服务商提供；
- 已过期窗口显示“已到期，等待刷新”，不得显示负数倒计时。

### E. 设置页阴影问题

修复设置窗口外框的阴影、描边、透明留白和圆角：

- 设置窗口和浮窗使用同一外轮廓半径 token；
- 四角不能出现直角黑块、白块或方形阴影；
- 阴影必须在窗口外缘可见但不覆盖内容；
- 浅色/深色主题都要检查；
- 保留窗口拖拽、缩放、关闭和首次打开无白屏闪烁。

只修改设置窗口的外框组合，不要重新引入旧的原生不透明标题栏或额外 CSS 末尾覆盖块。

### F. 任务栏字体：真实无极字重与字体备选

当前 GDI 链路实测只能稳定得到少数有效字重，现有 100–900 滑块不能继续作为“无极字重”对外承诺。Claude 必须先选择并验证真实可行的渲染路径：

1. 优先评估 DirectWrite/可变字体路径，使字重滑块在渲染结果上确实连续可见；
2. 增加字体族备选（至少系统 UI 字体、等宽字体、适合中文的字体），显示实际可用字体名称；
3. 字体族、字重、字号、对齐、宽度都要即时预览、持久化，并在任务栏实时重绘；
4. 如果 DirectWrite 在当前任务范围内无法安全完成，必须保留真实有效的离散字重并如实命名，不能再提供视觉无效的中间值；
5. 任务栏字体颜色、抗锯齿和背景继续跟随 Windows 任务栏，不增加会产生不透明色块的自定义底色。

验收必须用真实任务栏截图比较至少三档字重和两种字体，不能只通过设置页的 CSS 预览或单元测试宣称完成。

### G. 任务栏显示内容与多服务商组合

任务栏需要从“固定显示一种 usage”升级为用户可配置的显示组合：

- 每个条目由 `服务商 + 额度窗口` 组成，例如 `Codex · 5 小时`、`Codex · 周额度`、`Claude · 5 小时`；
- 可选择显示 5 小时、日、周、月、Credits/余额等服务商实际提供的窗口；
- 可多选多个服务商/窗口，并设置顺序；
- 提供清晰的默认组合、拖拽/上移下移、删除和恢复默认；
- 不可用、未启用或没有该窗口的条目应显示禁用原因，不得静默显示 0；
- 任务栏宽度不足时按明确规则截断或分行，不能遮挡系统托盘、制造缝隙或漂浮在任务栏上方；
- 任务栏、浮窗、仪表盘读取同一份格式化数据和服务商字段，但允许各自选择显示哪些字段、窗口和排序，不能各自拼接互相矛盾的文案。

建议的持久化形态是有序数组，而不是继续扩展一个三值 `taskbarWidgetContent` 字段；旧字段要有兼容迁移和恢复默认路径。

## 建议一并补充的基础能力

这些不是额外装饰，而是避免本轮再次返工的必要约束：

1. 加入统一的 `QuotaDisplayModel`/格式化层，集中处理 used、remaining、limit、resetsAt、resetDescription、预测和余额类型；前端卡片、任务栏和设置页只消费它。统一的是数据和术语，不是强制所有组件显示相同内容。
2. 所有展示都要区分 `loading`、`ready`、`stale`、`error`、`unsupported`；首次加载用占位，不要闪烁空卡片。
3. 为每个任务栏条目保留来源和更新时间，用户能看出是实时数据、缓存数据还是服务商不支持。
4. 统一中文、英文及其他 locale 的术语：使用量/剩余量、重置/到期、周额度/本周使用、余额/API key，不再出现同义词混用。
5. 每个组件的设置修改要即时作用于该组件已打开的窗口/任务栏，不要求重启；保存失败要回滚控件并给出错误提示。修改浮窗设置不能意外改变仪表盘或任务栏。
6. 对没有额度制度的 API 服务商保持现有余额/密钥状态卡，不为了统一外观而制造“使用百分比”。

### H. 设置页面重新分组：组件彼此独立

设置页面需要明确拆成三个互不混淆的功能区：

- **浮窗设置**：浮窗尺寸、密度、显示哪些服务商/额度窗口、已用量或剩余量、重置时间模式、预测和速度信息；
- **仪表盘设置**：仪表盘自己的服务商筛选、额度窗口、显示模式、卡片排序和详细程度；
- **任务栏设置**：任务栏开关、字体、宽度、对齐、条目组合、服务商/额度窗口选择和排序。

三块可以共享“恢复默认”和通用数据格式化组件，但每块必须有独立的持久化设置键和即时应用路径。不能让一个旧的 Display 全局开关悄悄覆盖三个组件，也不能让同名控件在不同页面代表不同语义。若保留全局默认值，必须标注为“新建组件时使用的默认值”，并允许组件级覆盖。
