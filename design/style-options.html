四个实现约束

  1. 描边用 box-shadow 的第一层，不要用 border。 真 border 会给面板加 2px 宽高并把内容内移 1px，破坏 k_geo 推出来的 padding: 12px 12px 11px。写成 box-shadow: 0 0 0 1px <描边色>, <投影> 则完全不影响布局， 现有 padding 一个数都不用改。
  2. 圆角要改两处。.menu-surface--tray .menu-card__zone 的 border-radius: 10px 之外，「Reference adaptation」段里 .menu-card--detailed .menu-card__zone--quota 和 --compact 各还有一条 border-radius: 10px，特异性更高， 漏改的话详细档不会生效。
  3. 背板色只能覆盖在 .menu-surface--tray 上。 它现在取自 --menu-popover-bg → --app-bg， 而 --app-bg 是全局令牌，设置页和 PopOut 都在用。改全局会波及那两个界面。
  4. 只影响详细档和紧凑档。极简档刻意不带 .menu-card__zone （见 MenuCard 的注释），这次不给它补面板。

验收

浅色下白面板压在 #eeeef0 背板上、深色下 #2c2c30 压在 #161618 上，两块面板应当明显浮起——这是本次唯一的目的。 对照标准就是本页 D 那两张卡。文字对比度不受影响（面板变亮只会提高浅色下的对比度； 深色下弱化文字实测 5.15:1）。

为什么现在显得沉闷：整张卡只有中性灰加一条蓝色进度条，颜色在全卡只出现两次（进度条、"用超"）。 最大的两块面板 rgba(0,0,0,.05) 与背板只差 5% 亮度，等于没有分层；所有数字都是同一个 --text-primary，没有主次。

约束：「用超」的焦糖橙 #a04000 / #ffa552 是上一轮按对比度定下来的，任何方向都不应该 再引入第三个暖色跟它抢；进度条的蓝/黄是状态语义色，也不能被装饰色占用。

对比度（已实测，全部 ≥ 4.5:1）：B 品牌名 #9a3412 5.87 / 次级文字 5.43，深色 5.76 / 5.11； C 数字 #0060df 4.63，深色 #4aa8ff 5.92；D 弱化文字 5.15； F 渐变块内小字 5.22–7.58，深色 4.84–7.67。
这里有两处是为了达标才偏离「好看的那个色」的：B 的品牌色填充用 #c2410c、文字用 #9a3412（前者作文字只有 4.16， 而 15px/700 仍达不到 WCAG 大字号豁免线）；F 的渐变比一般的蓝紫更暗（起点 #0552c4 而不是 #0a6cff， 后者托不住 11px 的白色小字，只有 3.1）。
